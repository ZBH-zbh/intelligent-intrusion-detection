# PL-PS 接口协议

本协议定义 PYNQ-Z2 上 FPGA（PL）与 ARM Python（PS）之间的数据交互方式。

## 1. 总体设计

- **视频数据流**：采用 AXI-Stream 接口传输 RGB 像素流
- **控制参数**：采用 AXI-Lite 接口配置算法参数
- **状态输出**：采用 AXI-Lite 接口读取处理结果

## 2. 视频流接口（AXI-Stream）

### 2.1 输入视频流

| 项目 | 说明 |
|---|---|
| 接口名称 | `in_stream` |
| 协议 | AXI4-Stream |
| 数据位宽 | 24 bit |
| 数据格式 | RGB888，即 `{R[7:0], G[7:0], B[7:0]}` |
| 分辨率 | 可配置，默认 640×480 |
| 像素传输顺序 | 从左到右、从上到下，逐行扫描 |
| TLAST | 每行最后一个像素置位 |

### 2.2 输出视频流（可选）

| 项目 | 说明 |
|---|---|
| 接口名称 | `out_stream` |
| 协议 | AXI4-Stream |
| 数据位宽 | 24 bit |
| 数据格式 | RGB888 |
| 内容 | 带标记的处理后画面（如二值化结果或画框后的画面） |

## 3. 控制寄存器（AXI-Lite）

| 偏移地址 | 名称 | 位宽 | 读写 | 默认值 | 说明 |
|---|---|---|---|---|---|
| `0x00` | `CTRL` | 32 | R/W | 0x0 | 控制启动/停止，bit0 = ap_start |
| `0x10` | `threshold` | 32 | R/W | 30 | 帧差二值化阈值 |
| `0x14` | `morph_kernel` | 32 | R/W | 5 | 形态学核大小（3 或 5） |
| `0x18` | `min_area` | 32 | R/W | 500 | 最小目标面积过滤阈值 |
| `0x1C` | `alarm_zone_x` | 32 | R/W | 0 | 警戒区域左上角 X 坐标 |
| `0x20` | `alarm_zone_y` | 32 | R/W | 0 | 警戒区域左上角 Y 坐标 |
| `0x24` | `alarm_zone_w` | 32 | R/W | 640 | 警戒区域宽度 |
| `0x28` | `alarm_zone_h` | 32 | R/W | 480 | 警戒区域高度 |
| `0x2C` | `frame_width` | 32 | R/W | 640 | 视频帧宽度 |
| `0x30` | `frame_height` | 32 | R/W | 480 | 视频帧高度 |

## 4. 状态寄存器（AXI-Lite）

| 偏移地址 | 名称 | 位宽 | 读写 | 说明 |
|---|---|---|---|---|
| `0x00` | `CTRL` | 32 | R/W | bit1 = ap_done，bit2 = ap_idle，bit3 = ap_ready |
| `0x34` | `target_count` | 32 | R/O | 当前帧检测到的运动目标数量 |
| `0x38` | `alarm_status` | 32 | R/O | 报警状态，0 = 正常，1 = 入侵 |
| `0x3C` | `reserved` | 32 | R/O | 保留 |
| `0x40` | `bbox_0_x` | 32 | R/O | 目标 0 左上角 X 坐标 |
| `0x44` | `bbox_0_y` | 32 | R/O | 目标 0 左上角 Y 坐标 |
| `0x48` | `bbox_0_w` | 32 | R/O | 目标 0 宽度 |
| `0x4C` | `bbox_0_h` | 32 | R/O | 目标 0 高度 |
| `0x50` | `bbox_1_x` | 32 | R/O | 目标 1 左上角 X 坐标 |
| ... | ... | ... | ... | 以此类推 |

> **说明**：假设最多支持 N 个目标，每个目标占用 4 个 32-bit 寄存器（x, y, w, h）。具体 N 值根据 FPGA 资源确定，初步设计为 N = 8。

## 5. 工作流程

```text
1. PS 配置控制寄存器（threshold、morph_kernel、alarm_zone 等）
2. PS 写 CTRL.ap_start = 1 启动 PL
3. PS 通过 AXI-Stream 发送一帧视频数据到 PL
4. PL 处理完成后，PS 读取 target_count 和 bbox 寄存器
5. PS 根据 alarm_status 控制 Grove Buzzer
6. PS 在 Jupyter 中绘制结果并显示
```

## 6. Python 调用示例

```python
from pynq import Overlay
import time

ol = Overlay("/home/xilinx/intrusion_detection.bit")
ip = ol.intrusion_detection_0

# 配置参数
ip.write(0x10, 30)    # threshold
ip.write(0x14, 5)     # morph_kernel
ip.write(0x18, 500)   # min_area
ip.write(0x1C, 100)   # alarm_zone_x
ip.write(0x20, 100)   # alarm_zone_y
ip.write(0x24, 200)   # alarm_zone_w
ip.write(0x28, 150)   # alarm_zone_h

# 启动 IP
ip.write(0x00, 0x01)

# 等待完成
while (ip.read(0x00) & 0x02) == 0:
    time.sleep(0.001)

# 读取结果
target_count = ip.read(0x34)
alarm_status = ip.read(0x38)
print("目标数量:", target_count)
print("报警状态:", alarm_status)

# 读取目标 0 坐标
x = ip.read(0x40)
y = ip.read(0x44)
w = ip.read(0x48)
h = ip.read(0x4C)
print("目标 0 框:", x, y, w, h)
```

## 7. 注意事项

- AXI-Stream 视频流需要与 AXI-Lite 控制寄存器配合使用
- PL 处理一帧数据期间，PS 不应修改控制参数
- bbox 寄存器数量需要根据实际 FPGA 资源调整
- 如果目标数量超过 N，PL 只返回前 N 个目标
