## 1. PYNQ 视频处理方案

### 1.1 两种视频输入方式

PYNQ-Z2 支持两种视频输入方式：

| 方式 | 接口 | 优点 | 缺点 |
|---|---|---|---|
| USB 摄像头 | USB HOST | 成本低、易获取、OpenCV 直接支持 | 带宽有限、延迟稍高 |
| HDMI IN | HDMI 输入 | 带宽高、延迟低 | 需要 HDMI 信号源、成本高 |

**本项目选择 USB 摄像头**，原因：
- 成本最低
- 罗技 C270i 即插即用
- OpenCV `cv2.VideoCapture(0)` 直接支持

### 1.2 PYNQ 视频输出方式

| 方式 | 说明 |
|---|---|
| Jupyter Notebook 显示 | 用 matplotlib/IPython 在浏览器显示，开发最方便 |
| HDMI OUT | 直接接显示器，适合现场演示 |

**开发阶段用 Jupyter 显示**，如果比赛现场有显示器，可以额外支持 HDMI OUT。

## 2. 为什么在 HLS 中用 AXI-Stream

### 2.1 AXI-Lite 不适合视频流

我们第一个学习 IP `rgb2gray` 用的是 **AXI-Lite**，通过 CPU 逐个像素写入寄存器。这种方式：
- 每个像素都要 CPU 参与
- 速度极慢，无法达到实时视频要求

### 2.2 AXI-Stream 适合视频流

AXI-Stream 是高速数据流接口：
- 不需要 CPU 逐个处理像素
- PL 内部可以流水线处理
- 适合连续的视频帧数据

### 2.3 HLS AXI-Stream 代码示例

```cpp
#include <ap_axi_sdata.h>

// 定义 24-bit RGB 像素类型
typedef ap_axiu<24, 0, 0, 0> pixel_t;

void frame_diff(
    pixel_t* in_stream,
    pixel_t* out_stream,
    int threshold,
    int frame_width,
    int frame_height
) {
    #pragma HLS INTERFACE axis port=in_stream
    #pragma HLS INTERFACE axis port=out_stream
    #pragma HLS INTERFACE s_axilite port=threshold bundle=CTRL
    #pragma HLS INTERFACE s_axilite port=frame_width bundle=CTRL
    #pragma HLS INTERFACE s_axilite port=frame_height bundle=CTRL
    #pragma HLS INTERFACE s_axilite port=return bundle=CTRL

    for (int i = 0; i < frame_width * frame_height; i++) {
        #pragma HLS PIPELINE II=1
        pixel_t p = in_stream->read();
        // 在这里处理像素
        out_stream->write(p);
    }
}
```

## 3. PL 内部处理流水线

```text
USB 摄像头 → PS OpenCV 采集
                ↓
         PS 发送 AXI-Stream 到 PL
                ↓
        ┌───────┴───────┐
        ↓               ↓
   RGB2Gray      背景帧缓存
        ↓               ↓
        └───────┬───────┘
                ↓
            帧差法 |diff|
                ↓
            二值化 threshold
                ↓
            形态学开运算/闭运算
                ↓
            连通域分析 / 轮廓提取
                ↓
        输出目标坐标 + 处理后视频流
                ↓
         PS 读取结果并显示
```

## 4. 帧差法算法原理

### 4.1 基本步骤

1. **灰度化**：将 RGB 转为灰度，减少计算量
2. **背景帧**：保存前一帧或固定背景帧
3. **差分**：`|current - background|`
4. **二值化**：差值大于阈值设为 255，否则为 0
5. **形态学**：去除噪声、填充空洞
6. **轮廓检测**：找到运动区域的外接矩形

### 4.2 Python 参考实现

```python
import cv2
import numpy as np

cap = cv2.VideoCapture(0)
ret, prev = cap.read()
prev_gray = cv2.cvtColor(prev, cv2.COLOR_BGR2GRAY)

while True:
    ret, frame = cap.read()
    gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
    
    # 帧差
    diff = cv2.absdiff(prev_gray, gray)
    _, binary = cv2.threshold(diff, 30, 255, cv2.THRESH_BINARY)
    
    # 形态学
    kernel = np.ones((5, 5), np.uint8)
    binary = cv2.morphologyEx(binary, cv2.MORPH_OPEN, kernel)
    binary = cv2.morphologyEx(binary, cv2.MORPH_CLOSE, kernel)
    
    # 轮廓与画框
    contours, _ = cv2.findContours(binary, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    for cnt in contours:
        if cv2.contourArea(cnt) > 500:
            x, y, w, h = cv2.boundingRect(cnt)
            cv2.rectangle(frame, (x, y), (x+w, y+h), (0, 255, 0), 2)
    
    prev_gray = gray.copy()
```

## 5. PL 与 PS 数据交互方案

### 方案 A：PL 只做预处理，PS 做轮廓检测

- PL：灰度化 + 帧差 + 二值化 + 形态学
- PS：读回二值图像，用 OpenCV 找轮廓画框
- **优点**：PL 设计简单，容易实现
- **缺点**：需要把每帧二值图传回 PS，带宽较大

### 方案 B：PL 完成所有图像处理，只输出坐标

- PL：灰度化 + 帧差 + 二值化 + 形态学 + 连通域/轮廓 + 输出 bbox
- PS：只读取坐标，在原图上画框
- **优点**：PS 负担最小，通信数据量小
- **缺点**：PL 内部需要实现连通域分析，复杂度较高

### 推荐方案

**先用方案 A**，把 PL 部分跑通后，如果时间充裕再挑战方案 B。
