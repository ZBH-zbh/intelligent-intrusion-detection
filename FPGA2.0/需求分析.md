# 需求分析

## 1. 项目背景

本项目面向 AMD/Xilinx 学生开发竞赛，基于 PYNQ-Z2 开发板设计一套**智能入侵检测系统**。系统利用 FPGA 可编程逻辑（PL）对视频流进行实时预处理加速，ARM 处理系统（PS）运行 Python 应用层逻辑，实现运动目标检测、入侵判断与报警功能。

## 2. 功能需求

### 2.1 核心功能

| 编号 | 功能 | 说明 |
|---|---|---|
| F01 | 视频采集 | 通过 USB 摄像头实时采集视频画面 |
| F02 | 运动目标检测 | 使用帧差法检测画面中的运动目标 |
| F03 | 目标定位 | 对检测到的运动区域绘制最小外接矩形框 |
| F04 | 目标计数 | 统计当前画面中的运动目标数量 |
| F05 | 入侵报警 | 划定警戒区域，当目标进入时触发报警 |
| F06 | 实时显示 | 在 Jupyter Notebook 中显示处理后的画面 |
| F07 | 蜂鸣器报警 | 通过 Grove Buzzer 输出声音报警 |

### 2.2 PL 端功能（FPGA 加速）

| 编号 | 功能 | 说明 |
|---|---|---|
| P01 | RGB 转灰度 | 将 24-bit RGB 视频流转换为 8-bit 灰度 |
| P02 | 帧差计算 | 当前帧与背景帧做差分 |
| P03 | 二值化 | 对差分结果进行阈值分割 |
| P04 | 形态学处理 | 开运算/闭运算去除噪声、连接断裂区域 |
| P05 | 目标信息输出 | 输出目标坐标、数量等元数据 |

### 2.3 PS 端功能（Python 应用）

| 编号 | 功能 | 说明 |
|---|---|---|
| S01 | 摄像头驱动 | 使用 OpenCV 读取 USB 摄像头 |
| S02 | 数据下发 | 将视频流传输给 PL 处理 |
| S03 | 结果解析 | 读取 PL 返回的目标坐标和数量 |
| S04 | 画框显示 | 在原画面上绘制目标框和区域线 |
| S05 | 入侵判断 | 判断目标是否进入警戒区域 |
| S06 | 报警控制 | 控制蜂鸣器开关 |
| S07 | 性能对比 | 对比 PS 纯软件与 PL 加速的性能 |

## 3. 性能需求

| 指标 | 目标值 | 说明 |
|---|---|---|
| 处理分辨率 | 640×480 或 320×240 | 根据实际帧率调整 |
| 目标帧率 | ≥ 15 FPS | 保证实时性 |
| 检测延迟 | ≤ 200 ms | 从采集到显示的端到端延迟 |
| 误检率 | 尽量低 | 通过形态学和参数调优控制 |
| 漏检率 | 尽量低 | 通过阈值和背景更新策略控制 |

## 4. 输入输出定义

### 4.1 输入

- **视频源**：USB 摄像头 RGB 视频流
- **分辨率**：640×480（默认），可配置为 320×240
- **控制参数**：
  - 二值化阈值（默认 30）
  - 形态学核大小（默认 5×5）
  - 警戒区域坐标与大小
  - 最小目标面积过滤阈值

### 4.2 输出

- **视频输出**：带框标记和区域线的 RGB 画面
- **目标信息**：
  - 目标数量
  - 每个目标的 bounding box（x, y, w, h）
- **报警状态**：
  - 0：正常
  - 1：有目标入侵警戒区域
- **报警动作**：Grove Buzzer 声音提示

## 5. 运行环境

### 5.1 硬件

- PYNQ-Z2 开发板
- 罗技 C270i USB 摄像头
- Grove Base Shield + Grove Buzzer
- 直连网线 + 5V 电源适配器

### 5.2 软件

- PYNQ-Z2 v3.0.1 系统镜像
- Vivado / Vitis HLS 2022.1
- Python 3.10
- OpenCV 4.x
- Jupyter Notebook

## 6. 约束条件

- 比赛评分注重 FPGA 加速部分，PL 需要承担主要的图像预处理计算
- 需要保留 PS 纯软件实现作为基准对比
- 代码和文档需要规范整理，体现大模型协作过程
- 项目需要在限定时间内完成并演示
