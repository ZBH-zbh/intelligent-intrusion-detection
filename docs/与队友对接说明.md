## 一、PYNQ 与硬件现状

### 1. PYNQ-Z2 板子现在能正常启动并访问 Jupyter 吗？IP 地址是多少？默认用户名密码是否还是 xilinx/xilinx？

- **能正常启动**，Jupyter 可以访问。
- IP 地址由路由器 DHCP 分配，不是固定的。查看方法：
  - 用 MobaXterm 连串口，登录后执行 `ifconfig`，看 `eth0` 或 `wlan0` 的 `inet addr`；
  - 或者登录路由器后台看设备列表。
- 默认用户名/密码：**xilinx / xilinx**。

### 2. USB 摄像头到货了吗？什么型号？是否已经在 PYNQ 上试过 `cv2.VideoCapture(0)`？

- 已到货，型号是 **罗技 C270i**。
- 已在 PYNQ 上测试通过，`cv2.VideoCapture(0)` 可以正常采集画面。
- 当前分辨率设置为 **320×240**，用于降低 PL 端处理压力和提升帧率。

### 3. Grove Buzzer 和 Grove Base Shield 到货了吗？蜂鸣器打算接在哪个 GPIO 引脚？

- 已到货。
- 蜂鸣器插在 **Grove Base Shield 的 G1 口**。
- G1 对应 **Arduino D2 = AR2 = Zynq PL 管脚 U13**。
- 控制方式：在自定义 overlay 中新增了一个 **AXI GPIO**，基地址 `0x40040000`，bit0 输出接到 U13，PS 通过 MMIO 直接控制蜂鸣器高低电平。

## 二、接口协议与方案选型

### 4. `docs/接口协议.md` 存在吗？里面方案 A / 方案 B 定了没有？

- `docs/接口协议.md` 存在，但里面的内容是最初的**理想化设计**（单 IP + PL 端输出 bbox）。
- **实际落地采用的是方案 A**：PL 端做 `rgb2gray → frame_diff → threshold → morphology` 四个 IP 级联，PS 端用 OpenCV 做轮廓提取、画框、报警判断。

### 5. 当前实际接口

#### 5.1 视频数据流

- 输入：PS 通过 AXI DMA 把一帧 RGB 图像发给 PL。
- 数据格式：**32-bit 0x00RRGGBB**（四个 IP 统一成了 32-bit AXI-Stream）。
- 分辨率：**320×240**。
- 传输方式：**AXI DMA MM2S → PL 流水线 → AXI DMA S2MM → PS**。

#### 5.2 AXI-Lite 控制寄存器（每个 IP 独立）

| IP | 基地址 | `width` 偏移 | `height` 偏移 | `threshold` 偏移 |
|---|---|---|---|---|
| rgb2gray | `0x40020000` | `0x10` | `0x18` | — |
| frame_diff | `0x40000000` | `0x10` | `0x18` | — |
| threshold | `0x40030000` | `0x10` | `0x18` | `0x20` |
| morphology | `0x40010000` | `0x10` | `0x18` | — |
| AXI GPIO（蜂鸣器） | `0x40040000` | — | — | — |
| AXI DMA | `0x41E00000` | — | — | — |

- `AP_CTRL` 偏移都是 `0x00`，写 `0x01` 启动。
- 每个 IP 的 AXI-Lite 地址空间大小为 `0x10000`（64K）。

#### 5.3 PS 端后处理输出

- PL 返回的是二值掩码（0/255），PS 用 `cv2.findContours` 提取目标框。
- 报警区域、目标数量、报警状态都在 PS 端计算。

## 四、Git 协作规范

### 7. 你们用的 Git 平台是什么？分支策略是什么？agent 提交代码时是否要开新分支 / 走 PR？

- 目前代码主要在本地的 Git 仓库管理，**还没有推送到远程平台**。
- 建议部署到 **Gitee 或 GitHub**（Gitee 国内访问更快）。
- 推荐分支策略：
  - `main`：主分支，保持可运行、可演示的稳定版本。
  - `feature/xxx`：新功能分支，例如 `feature/buzzer`、`feature/benchmark`。
  - 开发完成后通过 **Pull Request / Merge Request** 合并到 `main`。
- **agent 生成的代码建议先提到 feature 分支，不要直接 push 到 main**，等人 review 后再合并，避免把不能跑的中间版本带到主分支。

## 五、给队友的开发建议

### 纯软件 OpenCV 版本需要包含的功能

为了让软硬件对比公平，队友的 OpenCV 纯软件版本建议实现：

1. 摄像头采集（320×240）
2. RGB → 灰度（`cv2.cvtColor`）
3. 帧间差分（`cv2.absdiff`）
4. 二值化（`cv2.threshold`，阈值 30）
5. 形态学处理（`cv2.morphologyEx`，闭运算 + 开运算）
6. 轮廓检测与画框（`cv2.findContours`、`cv2.boundingRect`）
7. 警戒区判断与报警显示
8. FPS 统计输出

### 对比指标

| 指标 | 说明 |
|---|---|
| FPS | 连续运行 100~200 帧取平均 |
| CPU 占用 | 用 `top` 观察 `python` 进程 CPU% |
| 延迟 | 一帧从采集到显示的端到端时间（可选） |
| 检测效果 | 同一目标框位置、数量是否一致 |
